# Регистрация и вход — временный демонстрационный код

**Текущий режим: демонстрационный.** Настоящая локальная база данных
SQLite продолжает работать, но отправка кода на электронную почту
**временно отключена**. Это намеренное упрощение для разработки
десктопного WinForms-приложения, а не подтверждение владения почтой.

## Регистрация

1. Откройте экран **«ЗАРЕГИСТРИРОВАТЬСЯ»**.
2. Введите свободный логин, пароль длиной не менее восьми символов
   и адрес электронной почты.
3. Нажмите **«ПРИСЛАТЬ КОД НА ЭЛ. ПОЧТУ»**. Сейчас это формальное
   действие: письмо **не отправляется**, открывается четвёртое поле.
4. Введите **любое непустое значение кода**, например `test`,
   `123456` или `abc!7`, и нажмите **«ЗАРЕГИСТРИРОВАТЬСЯ»**.
5. После сохранения записи в SQLite **автоматически запускается анимация
   успешного входа**: четыре поля регистрации рассеиваются в снежную
   пыль, логин светится, увеличивается и переносится на майку.
6. После анимации пользователь **автоматически входит** и попадает
   в хоккейное меню («ЗАКАЗАТЬ АРЕНДУ», «ПРОФИЛЬ», «ИНФОРМАЦИЯ»,
   «РАСПИСАНИЕ ЗАНЯТИЙ»). Повторно вводить пароль и код не нужно.

Состояние текущей сессии хранится в памяти работающего приложения;
это **не** постоянный вход после его перезапуска.

Пустой код или строка только из пробелов не принимается. Система
по-прежнему проверяет обязательные поля, формат почты, минимальную
длину пароля и уникальность логина/адреса почты.

## Вход

1. Введите логин и пароль **ранее зарегистрированного аккаунта**.
2. Нажмите **«ПРИСЛАТЬ КОД НА ЭЛ. ПОЧТУ»**. Действительной отправки
   письма нет — отображается поле демонстрационного кода.
3. Введите **любое непустое значение** и нажмите **«ВОЙТИ»**.

Логин и пароль обязательно проверяются по SQLite. Произвольное
значение допустимо **только для поля кода** и не заменяет пароль.

## База данных

Файл автоматически создаётся в профиле Windows:

```text
%LOCALAPPDATA%\TerritoriyaHokkeya\users.db
```

Используется `Microsoft.Data.Sqlite` и таблица `Users`, содержащая
`Id`, `Login`, `Email`, `PasswordSalt`, `PasswordHash`,
`PasswordIterations`, `RegisteredUtc`.

Логин и почта уникальны без учёта регистра. Пароли **не сохраняются
открытым текстом**: применяется PBKDF2-HMAC-SHA256, 310 000 итераций
и индивидуальная случайная соль. SQL-запросы параметризованы.
База локальная: разные компьютеры не разделяют учётные записи.

## Почтовая отправка в будущем

В `App/AccountService.cs` установлен флаг
`HockeyAccountService.DemoVerificationEnabled = true`.
Он намеренно отключает отправку SMTP и проверку одноразового
значения кода. Почтовая реализация сохранена для будущей доработки;
её включение потребует отдельной настройки SMTP, повторной проверки
ограничения попыток и тестирования реальной доставки. Сейчас
SMTP-переменные окружения **не требуются**.

**Не применяйте этот режим для настоящих пользователей или
публичного сервиса.** Электронная почта фактически не подтверждена,
а код не создаёт дополнительной защиты. Это макет второго шага,
который позволяет разрабатывать интерфейс с реальным сохранением
пользователей в локальной базе.

## Проверки

Из корня `App_C#` в Windows, где установлен .NET 10 SDK:

```powershell
dotnet restore App/LP_PopovD_App.csproj
dotnet run --project Tests/AccountChecks.csproj -c Release
dotnet run --project Tests/StateChecks.csproj -c Release
dotnet run --project Tests/WinFormsChecks.csproj -c Release
dotnet run --project App/LP_PopovD_App.csproj -c Release
```

`AccountChecks` содержит отдельные сценарии настоящей проверки OTP
(с подставной доставкой) и **демонстрационного режима без писем**.
Он проверяет, что пользователь сохраняется в SQLite после любого
непустого кода, неверный пароль не даёт войти, а почтовая отправка
в демонстрационном режиме не вызывается.

Сборка и интерактивное тестирование WinForms не выполнялись в
рабочей среде ассистента из-за отсутствия .NET SDK и Windows.
