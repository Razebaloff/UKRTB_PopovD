# Регистрация и вход с подтверждением почты

Реализовано для **десктопной версии** `App/` (C# WinForms, .NET 10).

## Что действительно работает

1. На экране **Регистрация** заполните логин, пароль (не менее 8 символов)
   и адрес электронной почты.
2. Нажмите **«ПРИСЛАТЬ КОД НА ЭЛ. ПОЧТУ»**.
3. После успешной отправки письмо содержит случайный **шестизначный код**.
   Появляется четвёртое поле для его ввода. Срок действия — **10 минут**,
   допускается **не более пяти ошибочных попыток**.
4. Введите код и нажмите **«ЗАРЕГИСТРИРОВАТЬСЯ»**.
   Только после успешной проверки кода создаётся запись в SQLite.
5. После регистрации открывается экран **Вход**. Введите сохранённые
   логин и пароль: они сверяются с SQLite. На зарегистрированную почту
   отправляется новый код; после проверки выполняется вход в меню.

Коды создаются криптографически стойким генератором и существуют только
в памяти запущенного приложения в виде HMAC-SHA256 с одноразовым
случайным ключом. В БД и пользовательских настройках код не сохраняется.
При изменении логина, пароля или электронной почты ранее отправленный
код аннулируется. Повторная отправка ограничена 60 секундами **в рамках
одного запущенного экземпляра приложения**.

## Настройка отправки почты (обязательна)

Без SMTP-настроек **регистрация не сможет отправить код**, приложение
не показывает поддельное письмо или фиктивный успешный статус.

Перед запуском Visual Studio или `dotnet run` задайте переменные
окружения Windows для процесса приложения (пример для PowerShell):

```powershell
$env:HOCKEY_SMTP_HOST = "smtp.example.com"
$env:HOCKEY_SMTP_PORT = "587"
$env:HOCKEY_SMTP_USER = "mailbox@example.com"
$env:HOCKEY_SMTP_PASSWORD = "YOUR_APP_PASSWORD"
$env:HOCKEY_SMTP_FROM = "mailbox@example.com"

cd App
dotnet restore
dotnet run -c Release
```

Замените `smtp.example.com`, адрес и пароль действующими настройками
вашего почтового провайдера. Для порта **587** используется
`STARTTLS` (обязательно), для порта **465** — `SSL/TLS` с самого начала.
Проверка сертификата TLS не отключается. Требуется SMTP-аккаунт,
который разрешает аутентификацию обычным паролем приложения;
почтовые провайдеры с обязательным OAuth требуют дополнительной настройки
или изменения кода отправки.

**Не записывайте SMTP-пароль в исходники, GitHub, README или скриншоты.**
Если запускаете из Visual Studio, среда должна получить те же переменные
окружения, что и процесс программы.

## База данных

Приложение автоматически создаёт файл:

```text
%LOCALAPPDATA%\TerritoriyaHokkeya\users.db
```

Это **локальная SQLite**, а не база PostgreSQL из учебных лабораторных
работ. Таблица `Users` содержит `Id`, `Login`, `Email`,
`PasswordSalt`, `PasswordHash`, `PasswordIterations` и
`RegisteredUtc`. Логин и почта уникальны без учёта регистра;
запросы параметризованы. Пароль в открытом виде не хранится:
используется PBKDF2-HMAC-SHA256, 310 000 итераций и
индивидуальная 24-байтовая случайная соль.

Сохраняйте резервные копии `users.db`. Данные разных ПК **не
синхронизируются**. Для общего многопользовательского хоккейного сервиса
нужен отдельный сервер авторизации, централизованная БД и серверная
отправка/лимитирование OTP. Клиентская локальная SMTP-отправка не
предназначена для распространения приложения незнакомым пользователям
с общим почтовым секретом.

## Проверки

```powershell
dotnet run --project Tests/AccountChecks.csproj -c Release
dotnet run --project Tests/StateChecks.csproj -c Release
dotnet run --project Tests/WinFormsChecks.csproj -c Release
```

`AccountChecks` проверяет создание пользователя в SQLite **только после
верного кода**, отклонение неверных паролей и OTP, повторные регистрации,
отсутствие открытого пароля в файле БД и вход после регистрации.
Отправку письма он заменяет тестовым обработчиком, не требующим SMTP.

**Сборка и запуск в Windows пока не проверены в рабочей среде ассистента**:
здесь отсутствуют .NET SDK и WinForms. Реальную доставку письма на
конкретный SMTP-сервер необходимо проверить отдельно.
