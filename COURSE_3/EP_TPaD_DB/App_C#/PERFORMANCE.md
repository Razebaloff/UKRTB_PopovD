# Проверка анимаций — 01.11.2026

Windows Release-сборка: 0 предупреждений, 0 ошибок. Проверки логики: 31/31.
Дополнительно после исправления отмены: 104/104 проверки кэша сцен.

Программная отрисовка в Linux/libgdiplus, C# .NET 10; замер готовых кадров после прогрева.
В каждой серии 60 кадров, отдельно от подготовки сцены, записи PNG/GIF и оконного композитора.
Это время работы отрисовщика, а не измеренный FPS приложения в Windows.
Нагрузка среды меняется, поэтому значения нельзя переносить на другой ПК.

| Размер | Клюшки, медиана / p95, мс | Вход, медиана / p95, мс | Камера, медиана / p95, мс |
|---|---:|---:|---:|
| 960 × 540 | 1.6 / 2.8 | 1.9 / 3.5 | 7.3 / 10.5 |
| 1920 × 1080 | 2.7 / 3.7 | 3.5 / 6.7 | 13.9 / 17.4 |
| 3840 × 2160 | 7.4 / 11.2 | 9.9 / 17.5 | 17.5 / 20.5 |

Майка и варианты фона строятся заранее вне UI-потока. Клюшки используют небольшие подготовленные изображения;
при вращении перерисовывается только промежуток между флагами. Для камеры рабочая ширина ограничена
1280 px, а при ширине окна от 2560 px — 960 px; это уменьшает стоимость двух одновременно движущихся кадров.
Неподвижные экраны, первый/последний кадры и статический экспорт используют исходное разрешение.
Раскрытие поля кода смешивает только изменившийся участок в исходном разрешении.

Проверены 118 непрозрачных кадров анимации: 960 × 540, 1920 × 1080, 3840 × 2160.
Сравнение пикселей подтвердило сохранность обоих флагов и всех пикселей вне участка клюшек,
а также точное совпадение исходной и конечной позы в трёх размерах. Проверены длинные логины,
кириллица и Unicode. Все декодированные GIF-кадры сопоставлены с кадрами до упаковки.
Раскрытие поля кода проверено отдельно: флаги и первые два поля сохраняют точные исходные пиксели.

Поле пароля в превью содержит только вымышленные маскированные символы; код и логин — демоданные.
Само окно WinForms в Windows в этой среде не запускалось. Частота кадров на пользовательском ПК
и фактическое поведение нативных TextBox/CheckBox требуют проверки запуском в Windows.
Здесь не заявляется гарантированное отсутствие пропусков кадров на любом оборудовании.

## Исправление остановки Visual Studio при отмене

Отмена ожидающей подготовки при пересоздании окна раньше вызывала исключение из фоновой задачи.
Теперь старый кэш возвращает пустой результат без исключения; окно игнорирует такой результат.
При отмене уже построенное изображение освобождается, реальные ошибки отрисовки сохраняются.
Повторные уведомления об одном размере окна не пересоздают кэш.

Регрессионный тест на тех же исходниках воспроизводит отмену четырёх ожидающих кадров
в 20 циклах, проверяет обращения после Dispose и повторный Dispose, рабочее кэширование,
передачу настоящей ошибки и первичные исключения жизненного цикла.
До исправления: 101 неуспешная проверка из 104. После: 104/104, первичных исключений отмены — 0.
Тест выполнен в Linux/libgdiplus; Windows-проект теста и приложение собираются без предупреждений.

## Исправление шрифта чекбокса — 02.11.2026

Повторный вызов SetScale создавал равнозначный Font. Setter Control.Font в WinForms
сравнивает значения и в этом случае сохраняет прежний объект. Последующее освобождение
старого шрифта оставляло контрол со ссылкой на уже освобождённый GDI+ ресурс.
При открытии входа Graphics.DrawString выдавал ArgumentException.

Теперь при неизменном размере шрифт переиспользуется. Замена выполняется при реальном
изменении масштаба; предыдущий шрифт освобождается после назначения нового.
Аналогичные проверки размера уже используются кнопкой и полями ввода.

В Tests/WinFormsChecks.csproj добавлены 195 циклов для настоящих контролов из сборки приложения:
повторный масштаб, возврат к прежнему масштабу, DrawToBitmap, прямой OnPaint,
проверка шрифтов вложенных текстовых элементов и переключение чекбокса.
Это отдельная Windows-проверка, она не заменяется прежними тестами отрисовщиков.
**Проект теста и приложение собраны без ошибок и предупреждений. Сам Windows-тест
в этой Linux-среде не запускался; 31 проверка состояния выполнена успешно.**

Семантика setter проверена по [исходникам WinForms .NET 10](https://github.com/dotnet/winforms/blob/v10.0.0/src/System.Windows.Forms/System/Windows/Forms/Control.cs).

## Изменения по запросу от 02.11.2026

Изменён быстрый рендер перехода: ограничение промежуточного буфера 960 px
вместо 1280 px при Full HD, билинейная фильтрация, а снимок формы состоит
из готового фона и отдельных небольших контролов вместо полного DrawToBitmap.
В анимации входа сохранён фон в разрешении экрана, снежная динамика и
фрагменты полей объединены в отдельный буфер не шире 960 px.
Также увеличен конечный масштаб логина, световые лучи достигают границ
сцены, а два снежных потока идут от верхних углов к нижним.

Эти изменения сокращают объём отрисовки, но FPS на конкретном Windows-ПК
не измерялся; прежние результаты замеров относятся к предыдущему состоянию.
Для окончательной проверки: измерить длительность кадров в Visual Studio
на Full HD и 4K, проверить переходы мышью/клавиатурой, маскировку пароля,
центрирование флажка, отсутствие скачков первого и последнего кадров.

## Иней кнопок и метель клюшек — 02.11.2026

Кнопки (все RinkMenuButton, PuckButton и CapsuleButton) получили
плавный hover-эффект с независимой анимацией 285 мс. Кристаллический
рисунок один раз подготавливается в отдельном PArgb-слое при первом
наведении и повторно используется до изменения размера. Таймеры
работают только при изменении состояния hover и останавливаются после
завершения. При скрытии кнопок состояние инея сбрасывается.

Анимация клюшек теперь имеет дальние и ближние воздушные слои, широкие
полупрозрачные потоки, снежную пыль, направленные следы и снежинки
с ветвями. Используется существующий небольшой участок между флагами.
Физическое измерение FPS, интерактивный прогон и Release-сборка этого
изменения в Windows пока не выполнялись; прежние цифры производительности
на новую версию не переносятся.

## Устранение прямоугольных артефактов и плиток — 02.11.2026

При вращении клюшек фоновый снимок формируется без неподвижных клюшек,
вместо прямоугольного затирания готового кадра. Снежная метель
постепенно теряет прозрачность у границ области анимации.

Создание текстуры инея использует распределённые по всей поверхности
кристаллические ветви, а маска раскрытия доходит до центра шайбы.
При наведении есть несколько хаотично возникающих очагов роста.

Расщепление полей заменено попиксельной альфа-маской: вместо десятков
квадратных плиток используются по одной паре bitmap на панель и
дополнительные 380 мелких движущихся снежных частиц. Размер динамического
буфера остаётся не больше 960 px в ширину. Финальный кадр анимации входа
теперь создаётся в реальном разрешении формы, а не в уменьшенном буфере.

Структурная проверка C#-файлов выполнена, но сборка .NET и запуск WinForms
в данной среде недоступны. FPS и отсутствие артефактов в Windows пока не проверены.

## Резкость напечатанного логина и световые лучи — 02.11.2026

Исправлено видимое размытие логина на майке. В старой версии все буквы
создавались для рабочего буфера шириной 960 px, затем вместе со снегом
растягивались до разрешения окна. Теперь ветер и растворение полей
продолжают рендериться в лёгком 960 px буфере, а логин, нанесённая
надпись, свечение и световые лучи рисуются поверх этого буфера
непосредственно в нативном разрешении экрана. Текстуры букв подготавливаются
один раз с запасом разрешения, а для нанесённой надписи выборка ткани
выполняется из нативного кадра. Лучи теперь имеют неодинаковые длины,
ширину, яркость, направление и скорость мерцания, с короткими вторичными
ветвями; часть лучей достигает границ сцены.

Код проверен на баланс разделителей и ожидаемую структуру методов,
но .NET SDK в контейнере отсутствует; Windows-сборка, визуальная резкость
и фактические FPS этой редакции не подтверждены испытанием.
