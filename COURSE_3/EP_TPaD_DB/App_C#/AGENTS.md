# Правила оформления приложения «Территория хоккея»

Постоянные требования пользователя к последующим изменениям этого приложения:

- Не добавлять пунктирные, прерывистые или точечные линии по краям полей ввода и кнопок.
  Запрет действует во всех состояниях: обычном, при наведении, нажатии и фокусе с клавиатуры.
- Не использовать стандартный Windows focus rectangle и не имитировать его строчкой или швом.
  Кнопки обозначают фокус изменением тона, текстовые поля — кареткой.
- По последнему указанию пользователя возвращён вариант входа и регистрации с овальными
  тканевыми вставками в тон майки. Сохранять этот вариант; надписи без вставок отменены.
- Сохранять реальные элементы ввода, редактирование, Tab и маскировку пароля.
- При нажатии кнопки сначала полностью завершаются оборот клюшек и волна, затем выполняется действие
  и начинается переход. Эффект не захватывает флаги и не рисуется неподвижным слоем поверх камеры.
- Все файлы приложения сохранять в COURSE_3/EP_TPaD_DB/App_C# этого репозитория.
- Слева (слева направо) сохранять обратный порядок: школа Азаматова, Астра, Агидель, Толпар, Салават Юлаев.
  Использовать реальные исходные эмблемы, сохранять цвета и пропорции, без круглых подложек.
- Вход двухэтапный: «ПРИСЛАТЬ КОД НА ЭЛ. ПОЧТУ» → поле кода и «ВОЙТИ» → снежная сцена → главное меню.
  Пока это явно обозначенная демонстрация с любым непустым кодом, без отправки писем.
  Изменение логина/пароля сбрасывает запрос кода.
- «Запомнить меня» хранит только логин и флажок. Введённые пользователем пароль и код не сохранять в файлах,
  превью или журналах. Статический экспорт всегда показывает пустые поля.
- Не выполнять растеризацию льда/ткани или масштабирование больших исходников клюшек на каждом кадре.
  Сначала готовить фон и небольшие слои, затем запускать отсчёт анимации.
- Штатная отмена подготовки кадров при изменении размера или закрытии окна должна завершаться
  без throw. Возвращать пустой результат старого кэша и игнорировать его в окне;
  реальные ошибки отрисовки сохранять для обработки вызывающим кодом.
- При неизменном масштабе переиспользовать шрифт контрола. Не освобождать прежний Font
  после назначения равнозначного нового: WinForms может сохранить старый экземпляр в свойстве.

- Вход: центрировать флажок «ЗАПОМНИТЬ МЕНЯ» вместе с надписью на майке по горизонтали, сохраняя Y.
- На финальном этапе входа фрагменты полей физически разлетаются к нижним углам вместе со снежинками,
  снежная метель приходит из двух верхних углов. Имя заметно растёт при нанесении на майку,
  световые лучи расходятся по всему экрану. Следить за скоростью рендера, не пересоздавать фон на каждом кадре.
- Шрифт интерфейса возвращён к исходному Arial на всех экранах; длинная кнопка с кодом не должна обрезаться.
- При наведении мышью на каждую кнопку (шайбы, кнопки меню и овальные кнопки входа)
  слой инея плавно нарастает от края к центру, а при уходе курсора плавно исчезает.
  Узоры ледяных кристаллов кэшируются по размеру элемента и не пересоздаются на каждом кадре.
- При вращении клюшек используется не отдельное облако снежинок, а многослойная метель:
  пересекающиеся турбулентные струи, снежная пыль, длинные шлейфы и кристаллы.
  Все эффекты ограничены свободным промежутком между флагами, флаги не затрагиваются.

- Для анимации клюшек не затирать прямоугольную область поверх снимка формы:
  для движения сразу формировать фон без неподвижной пары, а метель гасить у границ эффекта.
- Иней должен закрывать целиком и шайбу, и овальную кнопку к концу наведения;
  кристаллическая текстура распределена также внутри, а не только по ободку.
- Поля ввода при удачном входе исчезают попиксельно, без крупных прямоугольных
  плиток. Использовать повторно создаваемую маску панели и движущиеся микрочастицы,
  а не сотни отдельных изображений плиток на каждом кадре.

- Во время успешного входа надпись логина и исходящие от её контура лучи рисовать
  отдельно в нативном разрешении окна. Фоновая метель и попиксельное растворение
  полей могут оставаться в буфере шириной до 960 px для сохранения FPS.
- Для печати логина на майке использовать заранее созданный масштабированный
  спрайт с запасом разрешения и модуляцией цвета по фактуре ткани без размытия
  альфа-контура букв. Лучи — с неодинаковыми длиной, интенсивностью и углом.

- При каждом запросе пользователя на изменения приложения сначала проверять доступ через
  подключённый GitHub, затем вносить изменения прямо в этот репозиторий и коммитить
  результат в main с реальной ссылкой на коммит. Не заменять коммит инструкциями
  по ручной вставке кода, когда доступ на запись работает.
- В анимации успешного входа снег должен быть широким и воздействовать на частицы
  расщепления полей физически: визуальная метель и движение отделившихся частиц
  используют одну геометрию и одно векторное поле ветра. В режиме покоя отдельные
  частицы не летят самостоятельно к нижним углам. Клюшки не менять без запроса.

- В сцене успешного входа две широкие снежные струи должны закручиваться
  в крупные спирали («кудри»), а не идти прямыми диагоналями. Продолжать
  использовать один ветер и для видимых струй, и для переноса микропыли.
- На ВСЕХ кнопках (шайбы, кнопки меню, овальные кнопки входа/регистрации)
  автоматически циклически появляется и тает иней; при наведении он
  уступает место самостоятельному эффекту ледяной корки. Поверх
  ледяного слоя заново отрисовывать текст, сохраняя его читаемым.
- На КАЖДОМ экране (Entry, Login, Registration, Menu) под ареной
  постоянно движутся русла лавы, видимые сквозь ледяной слой.
  Не рисовать лаву поверх майки, полей ввода или важных надписей.
  Использовать подготовленную повторяемую текстуру и один общий таймер,
  не растеризовать лёд заново на каждом кадре.

- Циклический иней на всех кнопках синхронный: одна общая фаза и общие
  времена появления/удержания/таяния; индивидуальный сдвиг времени запрещён.
- Лава заполняет весь фон всех экранов без прямоугольных ExcludeClip возле
  майки и центрального круга. Флаги, логотипы клубов, клюшки, майка,
  центральная разметка и надписи остаются поверх анимации посредством
  кэшируемого RGBA-слоя точной формы элементов, не прямоугольной маски.
- Лаву рисовать как хаотичные неоднородные каналы с ветвлениями,
  холодной пористой коркой и горячими прожилками, используя периодический
  шум и отдельные скорости движения слоёв; без обычных прямых линий и
  декоративных круглых точек. Сохранять лёгкое голубое покрытие для
  впечатления лавы ПОД ледяной поверхностью.

## Актуальная настройка эффектов — 02.11.2026 (имеет приоритет над прежними пунктами)

- **Лава временно выключена по прямому запросу пользователя.** Не вызывать
  LavaUnderIceDrawing из Form1, не запускать её таймер, не расходовать на неё
  время отрисовки. Исходник LavaUnderIceDrawing.cs сохранить для отдельной
  будущей доработки; прежние требования о постоянно видимой лаве пока отменены.
- Фоновый иней всех видимых кнопок синхронизирован и обновляется одним общим
  WinForms Timer с интервалом 16 мс. Не создавать Timer для каждой кнопки.
- На каждом кадре только смешивать готовые bitmap-слои инея и заледенения
  с изменяемой прозрачностью. Ветвящиеся кристаллы, ледяные трещины и контуры
  надписей создавать один раз при изменении текста или размера.
- При перерисовке отдельной кнопки не отрисовывать клюшки, если кнопка не
  пересекается с их экранной областью. Текст на кнопках всегда над ледяным
  слоем. FPS и плавность проверять на Windows, не заявляя замеры без теста.

## Актуальные требования к инею и трещинам — 03.11.2026

- Фоновый иней на кнопках больше НЕ появляется/тает одним сплошным
  слоем. Независимые микрокристаллы оседают в разных точках,
  разрастаются, недолго сохраняются и постепенно тают. Новые циклы
  создают новые точки выпадения при стабильной детерминированной
  генерации. Прежнее требование о синхронном проявлении ВСЕГО инея
  отменено; общий таймер остаётся для производительности.
- При наведении на шайбы поверх фонового инея возникает ледяная
  корка, а по льду ВОКРУГ шайбы расходятся ветвящиеся трещины.
  Трещины рисуются на Form1 за границами круглого Region шайбы,
  иначе WinForms их обрезает. На уходе курсора эффект исчезает.
- Реалистичная геометрия создаётся и кэшируется один раз на размер
  элемента. Не формировать сотни GraphicsPath, Text или Bitmap
  заново на каждом тике. UI-таймер один на все кнопки, пересчёт
  по Stopwatch; не объявлять фактические FPS без испытаний.
- Анимация лавы остаётся отключённой до отдельного запроса.

## Актуальные требования к клавиатуре и морозным узорам — 03.11.2026 (последняя редакция)

- На поверхности каждой кнопки фоновый иней должен выглядеть как
  тонкие хаотично разрастающиеся и тающие **ветвящиеся линии**, как
  морозные узоры на оконном стекле, а НЕ шестилучевые снежинки,
  равномерный белый налёт или синхронное затемнение всей поверхности.
- Линии должны быть достаточно контрастны и заметны на тёмной кнопке
  «ПРИСЛАТЬ КОД НА ЭЛ. ПОЧТУ», но находиться ПОД надписью.
  Продолжать использовать индивидуальные временные циклы и новые
  точки зарождения при каждом цикле.
- При наведении лёд должен постепенно расходиться неровными островами
  и смыкаться, а не появляться одной прозрачной плёнкой. Для шайб
  продолжать рисовать отдельные расходящиеся трещины на родительском
  фоне. Надписи кнопок всегда поверх заледенения.
- **Tab и Shift+Tab** должны обходить все доступные для текущего экрана
  кнопки и текстовые поля: Entry — три шайбы; Login — логин, пароль,
  при необходимости код, «запомнить меня», отправка/вход, назад;
  Registration — логин, пароль, почта, регистрация, назад;
  Menu — аренда, профиль, информация, расписание, назад.
  UserControl текстового поля должен передавать фокус своему TextBox.
  Enter в авторизации может активировать Submit; на других экранах
  Enter активирует текущую кнопку. Нужна видимая клавиатурная подсветка
  без стандартной синей прямоугольной рамки.
- По-прежнему не включать лаву без отдельного запроса. Изменения
  десктопного WinForms-приложения не заменяют файлы в Mobile/.

## Текущие правила для шайб и заледенения — 03.11.2026 (приоритет над прежними)

- Фоновое появление и таяние ледяных прожилок на круглых кнопках
  замедлено относительно овальных (коэффициент времени 1,65).
  При наведении на шайбы корка и расходящиеся трещины образуются
  плавнее: длительность анимации 900 мс против 285 мс на обычной кнопке.
- Убрать любую БЕЛУЮ КОНТУРНУЮ линию, появляющуюся при наведении:
  ледяная корка должна иметь мягкий край без белого обода.
- Убрать БЕЛЫЙ ПУНКТИРНЫЙ круг у кнопки «ВОЙТИ» и пунктирные
  обводки фокуса на кнопках. Сохранить видимый Tab-фокус
  изменением цвета и подсветкой поверхности, без контурной рамки.
- Не допускать квадратов по бокам овальных кнопок: все 16
  подготовленных кадров ледяных островов и их смешивание строго
  клиппировать к круглой/капсульной форме. Сохранять альфа-канал;
  пиксели за формой не должны перерисовываться.
- Исходники мобильной версии и отключённой лавы не изменять.

## Актуальные требования к кнопкам, Tab и выравниванию — 03.11.2026 (приоритетные)

- По последнему запросу **общее заледенение при наведении отключено** на
  обычных кнопках меню и отправки кода/регистрации. Постоянные хаотично
  растущие и тающие морозные прожилки сохраняются. Исключения:
  *стартовые шайбы* (по-прежнему с медленным ледяным эффектом и
  трещинами вокруг) и овальная кнопка **«НАЗАД»** (с таким же медленным
  поэтапным образованием льда при наведении, длительность 900 мс).
- На кнопке «ПРИСЛАТЬ КОД НА ЭЛ. ПОЧТУ» узор НЕ пересекает зону
  текста: рисование фоновых прожилок ограничено маской с исключённым

- Вложенный TextBox — единственная остановка Tab внутри CapsuleInput.
  Сама оболочка UserControl имеет TabStop=false; Form1 не включает
  его обратно для оболочек. Активное поле отмечено тонкой голубой
  линией по форме овального поля, без дополнительных элементов слева.
- Три шайбы экрана Entry лежат на **одной горизонтали**:
  центры в координатах сцены (300,445), (800,445), (1300,445).
  Все размещения берутся из EntryDrawing.PuckCenters, без отдельных
  хардкодных позиций в Form1.
- Не включать лаву, не редактировать Mobile/ по запросам к десктопу.

- **Никакой голубой плёнки/корки при наведении на шайбы и на кнопку

  отключены. На стартовых шайбах остаются только ветвящиеся трещины

- Три шайбы стартового экрана по одной линии: «ВОЙТИ» слева

  индексы [0]=ВОЙТИ, [1]=ЗАРЕГИСТРИРОВАТЬСЯ, [2]=РАСПИСАНИЕ.
- **Tab/Shift+Tab обязаны заходить непосредственно в настоящий TextBox**

  TextBox.PlaceholderText. Не добавлять в поля декоративные контролы,
  скобки или боковые рамки. Фокус поля показывается тонким маркером

- На «ПРИСЛАТЬ КОД НА ЭЛ. ПОЧТУ» запрещено прямоугольное исключение

- Лава по-прежнему отключена, Mobile/ независимо от настольной версии.

## Регистрация/вход и трещины у «НАЗАД» — 03.11.2026 (текущие требования)

- На экране **Регистрация** сначала логин, пароль и почта; первый
  submit отправляет **настоящий 6-значный OTP** через настроенный
  SMTP и раскрывает четвёртое поле. Только после проверки кода
  второй submit создаёт пользователя в **локальной SQLite**.
- При отсутствии SMTP-параметров НЕ симулировать отправку кода и
  НЕ регистрировать аккаунт; выводить ошибку. Настройка SMTP
  документирована в AUTH_SETUP.md. Секреты не записывать в GitHub.
- Хранить пароли только PBKDF2-HMAC-SHA256 + индивидуальная соль.
  Логины и адреса почты уникальны; SQL-запросы параметризованы.
  OTP 10 минут / 5 попыток / 60 секунд между отправками
  (последний лимит действует в пределах одного экземпляра).
- Вход проверяет логин и пароль в SQLite, после этого отправляет
  новый OTP на сохранённую почту. Старый демонстрационный сценарий
  с произвольным непустым кодом больше не используется для входа.
- На «НАЗАД» при наведении появляются **только ветвящиеся
  расходящиеся трещины на льду за пределами капсулы**, не голубая
  плёнка и не замораживание текста. Механика согласована
  с PuckCrackDrawing, создаётся заранее и обрабатывается Form1.
- Мобильную версию не менять, лаву не включать.
