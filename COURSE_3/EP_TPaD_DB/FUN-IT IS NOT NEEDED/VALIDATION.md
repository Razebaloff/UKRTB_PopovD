## Автоматизированное прохождение кампании

Проверочный игрок строит и улучшает башни только через обычные игровые команды, не получает дополнительного золота и не обнуляет откаты. Выбран герой Лиора. Ранг каждого постоянного улучшения равен `min(3, номер_карты_с_нуля / 3)`; такая стоимость доступна за звёзды предыдущих уровней. Это проверка проходимости конкретной стратегией, а не доказательство идеального баланса всех вариантов.

## Границы проверки

Работа выполнена в Linux. **Запуск окна Windows Forms, вывод звука на устройстве и ручное прохождение на Windows не проверены.** Компиляция интерфейса не заменяет эти проверки.

Штатный `dotnet build` в данной среде завершается внутри SDK при чтении сведений о процессе (`System.Diagnostics.Process`), до компиляции проекта. Поэтому использован прямой запуск того же Roslyn с официальными reference assemblies. Это ограничение среды проверки; успешная компиляция исходников и успешное исполнение проверок логики подтверждены отдельно. Сборка решения через Visual Studio на Windows здесь не запускалась.

Готовая сборка требует установленного .NET Desktop Runtime. Автономный EXE со встроенной средой создаёт `Publish-Windows.ps1`; его публикация здесь не выполнялась. Обновление обычной готовой сборки из исходников: `Build-Ready.ps1`.
